# Этап 3. Деобфускация кода

## Шаг 3.2. Декодирование и описание угрозы

### 1. Расшифрованная строка
После декодирования строки из переменной `a` из формата Base64 получается следующий код:

```python
import os; os.system('rm -rf /')
```

### 2. Описание угрозы безопасности
Данный скрипт несет **критическую угрозу** (категории Remote Code Execution / Arbitrary Code Execution). Если запустить этот код от имени пользователя с правами суперпользователя (`root`), выполнится системная команда Linux/Unix:

`rm -rf /`

*   `rm` — команда удаления файлов и директорий.
*   `-r` — рекурсивное удаление (включая все вложенные папки).
*   `-f` — принудительное удаление без подтверждения и вывода предупреждений.
*   `/` — корневой каталог операционной системы.

**Последствия:** Скрипт попытается полностью стереть все данные с жесткого диска, включая файлы самой операционной системы, пользовательские данные и подключенные диски. Это приведет к полному уничтожению системы и потере данных.

## Методы защиты от подобных атак

Чтобы не допустить выполнения такого вредоносного кода, можно использовать следующие подходы:

1. **Полный запрет или ограничение функции `exec()` и `eval()`**
   Использование `exec()` для динамического выполнения кода, переданного в виде строки (тем более закодированной), считается худшей практикой. В безопасном коде эти функции должны быть полностью исключены.
   
2. **Использование статического анализа (SAST)**
   Линтеры и специализированные сканеры безопасности (например, [Bandit для Python](https://readthedocs.io "Bandit Security Scanner")) умеют автоматически находить вызовы опасных функций вроде `exec`, `eval` или `os.system`, а также подсвечивать подозрительные строки в Base64. Они заблокируют деплой такого кода еще на этапе сборки.

3. **Запуск в изолированной среде (Песочницы / Контейнеризация)**
   Если приложение обязано выполнять сторонний код, его нужно запускать строго внутри изолированных контейнеров (например, Docker) с минимальными системными привилегиями (non-root пользователь) и ограничением прав на запись в системные директории (read-only файловая система).
