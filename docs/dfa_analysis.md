# Этап 1. Анализ потоков данных (Data Flow Analysis)

## Шаг 1.2. Цепочки Def-Use

Анализ определений (Def) и использований (Use) для всех переменных в коде:

*   **user_id**
    *   Def: строка 1 (аргумент функции)
    *   Use: строка 6 (внутри get_balance), строка 8 (внутри update_balance)
*   **amount**
    *   Def: строка 1 (аргумент функции)
    *   Use: строка 4 (проверка в условии if), строка 7 (расчет нового баланса)
*   **db_connection**
    *   Def: строка 1 (аргумент функции)
    *   Use: нигде не используется (лишний параметр)
*   **log_entry**
    *   Def: строка 2 (первичное присваивание), строка 10 (перезапись строки статуса)
    *   Use: строка 13 (при записи в файл через write)
*   **status**
    *   Def: строка 5 (внутри блока if)
    *   Use: строка 10 (сборка строки лога), строка 15 (возврат из функции)
*   **balance**
    *   Def: строка 6 (получение текущего баланса)
    *   Use: строка 7 (вычитание суммы amount)
*   **new_balance**
    *   Def: строка 7 (результат вычитания)
    *   Use: строка 8 (передача в функцию обновления)
*   **file**
    *   Def: строка 12 (открытие файла на запись)
    *   Use: строка 13 (вызов метода .write())


## Шаг 1.3. Дефекты, найденные с помощью DFA

1. **Обращение к неинициализированной переменной**
Ошибка выстрелит на 10-й строке (при конкатенации строки) и на 15-й строке (в return), если на вход придет `amount <= 0`. В таком случае условие `if` просто не выполнится, программа проскочит 5-ю строку и переменная `status` вообще не создастся. При попытке прочитать ее Python выдаст ошибку `UnboundLocalError`.

2. **Мертвое присваивание (Dead Store)**
На 2-й строке переменной `log_entry` присваивается значение `"Start processing"`. Но это значение дальше нигде не читается и не выводится, а на 10-й строке эта же переменная просто затирается новым текстом. Получается, что первая строчка кода вообще не имеет смысла и просто впустую тратит память.

3. **Утечка ресурса (Resource Leak)**
На 12-й строке через `open()` открывается файл `audit_log.txt`. При этом в конце функции забыли вызвать `file.close()`, а сам файл открыт без менеджера контекста `with`. Из-за этого дескриптор файла зависает открытым в системе, пока скрипт полностью не завершится или сборщик мусора его не закроет, что плохо для стабильности программы.
