# Этап 2. Чтение ассемблерного кода (Дизассемблирование)

## Шаг 2.2. Восстановление логики

После анализа ассемблерных инструкций (архитектура x86-64, синтаксис AT&T) логика работы кода выглядит следующим образом:

1. **Инициализация переменных на стеке:**
   * `-4(%rbp)` — это аккумулятор (сумма). Ему присваивается 0 (`movl $0, -4(%rbp)`).
   * `-8(%rbp)` — это счетчик цикла (итератор). Ему присваивается 1 (`movl $1, -8(%rbp)`).

2. **Управление циклом:**
   * Программа сразу прыгает к метке `.L2` через `jmp`, где происходит проверка условия.
   * `cmpl $10, -8(%rbp)` сравнивает значение счетчика с числом 10.
   * `jle .L3` (Jump if Less or Equal) переводит управление на метку `.L3`, если счетчик меньше или равен 10. То есть цикл крутится, пока `i <= 10`.

3. **Тело цикла (метка `.L3`):**
   * Значение счетчика переносится в регистр `%eax` и прибавляется к сумме (`addl %eax, -4(%rbp)`).
   * Счетчик увеличивается на 1 (`addl $1, -8(%rbp)`).

4. **Выход из функции:**
   * Когда счетчик становится больше 10, цикл завершается.
   * Финальная сумма из аккумулятора переносится в регистр `%eax` (`movl -4(%rbp), %eax`), который традиционно используется в x86-64 для возврата значения из функции.

**Итог:** Код просто считает сумму чисел от 1 до 10 включительно (результат будет равен 55).

---

## Эквивалентный код на Python

```python
def calculate_sum():
    total_sum = 0
    i = 1
    
    while i <= 10:
        total_sum += i
        i += 1
        
    return total_sum
```

*(Примечание: логику также можно записать через более лаконичный `sum(range(1, 11))`, но структура `while` в Python в точности повторяет шаги ассемблерных переходов `jmp` и `jle` с проверкой счетчика).*
